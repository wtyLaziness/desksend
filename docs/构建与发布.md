# 构建与发布

用户直接下载[完整便携包](https://github.com/wtyLaziness/desksend-releases/releases/latest)即可。本页供开发者构建和验证修改。

## 目录与版本

产品版本由 `deskflow-master/cmake/DeskSendVersion.cmake` 定义。GUI 输出为 `DeskSend.exe`，核心为 `deskflow-core.exe`，文件传输组件为 `localsend-cli.exe`。

Deskflow 和 LocalSend 子目录保留上游源码结构及许可证。上游构建细节分别见 [Deskflow 构建说明](../deskflow-master/docs/dev/build.md) 和 [LocalSend README](../localsend-main/README.md)。

## GitHub Actions

当前 Windows 构建流程以以下工作流为准：

| 工作流 | 内容 |
| --- | --- |
| [`deskflow-win`](../.github/workflows/deskflow-win.yml) | MSVC x64、Qt 6.8 系列、CMake/Ninja、单元测试与 ZIP 产物 |
| [`localsend-cli-win`](../.github/workflows/localsend-cli-win.yml) | Rust CLI 构建、单元测试、32 MiB 同机发送接收及哈希核对 |
| [`phase0-loopback`](../.github/workflows/phase0-loopback.yml) | 手动执行的拖拽、取消、回切、重连与品牌回归 |

运行回环前，两个构建工作流必须对同一完整提交 SHA 成功。若只修改测试脚本，可用 `binaries_commit` 指向生产源码相同的已构建提交；工作流会检查源码一致性。

`compare_1_0_0` 是可选的历史对照，用于确认旧版会在反向抖动时取消拖拽。它依赖历史 Actions 产物，产物过期后不能使用；默认不启用。

## 本机 Windows 构建

使用已准备好 x64 MSVC、Ninja、CMake、Qt 和 vcpkg 的开发环境。以下 Qt、vcpkg 路径仅为示例，请替换为实际位置；工具和依赖版本约束以源码及工作流为准。

```powershell
$qtDir = 'C:/Qt/6.8.3/msvc2022_64'
$vcpkgDir = 'C:/src/vcpkg'
$env:PATH = "$qtDir/bin;$env:PATH"
cmake -S deskflow-master -B deskflow-master/build -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_INSTALLER=ON -DBUILD_TESTS=ON -DCMAKE_PREFIX_PATH="$qtDir" -DCMAKE_TOOLCHAIN_FILE="$vcpkgDir/scripts/buildsystems/vcpkg.cmake"
cmake --build deskflow-master/build
```

构建默认执行单元测试。生成基础 ZIP：

```powershell
Push-Location deskflow-master/build
cpack -G ZIP
Pop-Location
```

Rust 工具链由 `localsend-main/rust-toolchain.toml` 指定。在 LocalSend 工作区执行：

```powershell
Push-Location localsend-main
rustup toolchain install
cargo test --release --package localsend-cli
cargo build --release --package localsend-cli
Pop-Location
```

若修改核心协议 crate，应额外在 `localsend-main/packages/core` 中运行 `cargo test --features full`，保留已有的 Cargo workspace 结构。

## 组装完整包

基础 Deskflow ZIP 不包含 LocalSend CLI，不能当作 DeskSend 完整包分发。下载同一提交的两个构建产物后运行：

```powershell
python phase0/package-release.py --deskflow-zip <基础ZIP路径> --localsend-exe <localsend-cli.exe路径> --build-commit <完整提交SHA> --out <新的输出目录>
```

该脚本使用 Python 标准库，生成完整 Windows ZIP、对应源码 ZIP 和 `SHA256SUMS.txt`。输出目录必须是新的。脚本验证完整组件、生产源码与构建提交的一致性，并检查源码包不含证书和运行日志。

`desksend-build.json` 记录构建提交、源码提交和可覆盖程序文件的哈希。`settings` 不在自动更新的覆盖清单中。

更新安装逻辑可用 `phase0/update-test.ps1` 验证。产品入口和版本可用 `phase0/branding-test.ps1` 检查。真实双机测试还应覆盖防火墙、桌面/资源管理器落点以及实际鼠标行为。

## 发布

开发仓库为 [wtyLaziness/desksend](https://github.com/wtyLaziness/desksend)，下载与更新仓库为 [wtyLaziness/desksend-releases](https://github.com/wtyLaziness/desksend-releases)。

通过维护者已登录的 GitHub CLI 创建发布草稿，上传完整包、对应源码和校验文件，核对后公开。标签为 `v<版本>`，完整包必须名为 `DeskSend-<版本>-windows-x64.zip`，与客户端更新解析规则一致。不要把维护者 token 放进应用或仓库。

更新协议、安装与备份细节见 [DeskSend 发布说明](../DeskSend-发布说明.md)。
