# 构建与发布

Windows 用户可以下载[完整便携包](https://github.com/wtyLaziness/desksend-releases/releases/latest)即可。本页供开发者构建和验证修改。

## 目录与版本

产品版本由 `deskflow-master/cmake/DeskSendVersion.cmake` 定义。GUI 输出为 `DeskSend.exe`，核心为 `deskflow-core.exe`，文件传输组件为 `localsend-cli.exe`。

Deskflow 与 LocalSend 子目录保留对应组件的源码与许可证；本仓库仅保留构建 `localsend-cli` 所需的 Rust CLI 与核心协议 crate（`cli/` 与 `packages/core/`）。上游构建说明见 [Deskflow 构建说明](../deskflow-master/docs/dev/build.md) 与 [LocalSend 上游仓库](https://github.com/localsend/localsend)。

## GitHub Actions

| 工作流 | 构建、测试与产物 |
| --- | --- |
| [`deskflow-win`](../.github/workflows/deskflow-win.yml) | Windows x64。构建 LocalSend CLI 和 DeskSend，生成 ZIP 与 MSI，检查 MSI 安装文件和服务，直接运行已安装服务的退出测试，并检查卸载。 |
| [`localsend-cli-win`](../.github/workflows/localsend-cli-win.yml) | Windows x64。运行 Rust 单测、32 MiB 本机回环传输及 stdin 鉴权传输，检查进度、哈希和内容。 |
| [`deskflow-macos`](../.github/workflows/deskflow-macos.yml) | macOS arm64。运行 Rust 单测和普通、鉴权回环 E2E，使用 CMake 构建 DeskSend，以 offscreen 模式运行 CTest，检查并归档 `DeskSend.app`。 |
| [`deskflow-linux`](../.github/workflows/deskflow-linux.yml) | Linux x64。从指定源码提交构建并缓存 libei 1.6.0 和 libportal 0.10.0，运行 Rust 单测和普通、鉴权回环 E2E，使用 CMake 构建 DeskSend，在 Xvfb 下运行 CTest，检查并归档安装目录。 |

macOS 和 Linux 的工作流均检查 GUI、核心和 `localsend-cli` 的可执行权限及 LocalSend 许可证。回环 E2E 在单台 runner 上执行，跨系统互传、原生拖拽和桌面落点需在实机上验收。

macOS 和 Linux 可参考各自工作流从源码构建。先编译 `localsend-cli`，再通过 `-DDESKSEND_LOCALSEND_CLI=<绝对路径>` 将其纳入 DeskSend 安装产物。打包和运行时通过环境变量 `DESKSEND_LOCALSEND_CLI` 覆盖时，均使用与 DeskSend 同一源码版本配套的 CLI。DeskSend 调用的无损路径帧需要 `--paths-stdin-hex` 和 `--received-paths-hex`，CLI 的默认行格式保留供既有调用使用。

## 本机 Windows 构建

使用已准备好 x64 MSVC、Ninja、CMake、Qt 和 vcpkg 的开发环境。以下 Qt、vcpkg 路径仅为示例，请替换为实际位置；工具和依赖版本约束以源码及工作流为准。

```powershell
$qtDir = 'C:/Qt/6.8.3/msvc2022_64'
$vcpkgDir = 'C:/src/vcpkg'
$env:PATH = "$qtDir/bin;$env:PATH"
cmake -S deskflow-master -B deskflow-master/build -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_INSTALLER=ON -DBUILD_TESTS=ON -DCMAKE_PREFIX_PATH="$qtDir" -DCMAKE_TOOLCHAIN_FILE="$vcpkgDir/scripts/buildsystems/vcpkg.cmake"
cmake --build deskflow-master/build
```

构建默认执行单元测试。生成基础 ZIP：

```powershell
Push-Location deskflow-master/build
cpack -G ZIP
Pop-Location
```

Rust 工具链由 `localsend-main/rust-toolchain.toml` 指定。在 LocalSend 工作区执行：

```powershell
Push-Location localsend-main
rustup toolchain install
cargo test --release --package localsend --package localsend-cli
cargo build --release --package localsend-cli
Pop-Location
```

若修改核心协议 crate，应额外在 `localsend-main/packages/core` 中运行 `cargo test --features full`，保留已有的 Cargo workspace 结构。

需要构建可处理 UAC 的安装版时，使用 CMake 3.30 或更新版本，并准备 WiX 4 及同版本的 `WixToolset.UI.wixext`、`WixToolset.Util.wixext` 和 `WixToolset.Firewall.wixext`。构建出 LocalSend CLI 后，在上面的 CMake 配置命令追加 `-DDESKSEND_LOCALSEND_CLI=<localsend-cli.exe 的绝对路径>`，构建完成后在构建目录中执行 `cpack -G WIX`，生成 `DeskSend-<版本>-windows-x64.msi`。Actions 安装包产物名为 `desksend-windows-x64-msi`。

安装版实机验收时，副机开启后台服务及“始终以系统身份运行”，核对普通桌面、UAC 出现前后键鼠连接和点击，以及双向跨屏拖文件。

## 组装完整包

基础 Deskflow ZIP 不包含 LocalSend CLI，不能当作 DeskSend 完整包分发。下载同一提交的两个构建产物后运行：

```powershell
python scripts/package-release.py --deskflow-zip <基础ZIP路径> --deskflow-msi <MSI路径> --localsend-exe <localsend-cli.exe路径> --build-commit <完整提交SHA> --out <新的输出目录>
```

脚本生成完整 Windows ZIP、对应源码 ZIP 和 `SHA256SUMS.txt`。提供 `--deskflow-msi` 时，脚本也会将安装包和对应校验值纳入交付。输出目录下的 `DeskSend-<版本>-windows-x64` 子目录必须不存在，避免覆盖已有组装结果。脚本验证完整组件、生产源码与构建提交的一致性，并检查源码包不含证书和运行日志。

`desksend-build.json` 记录构建提交、源码提交和可覆盖程序文件的哈希。`settings` 不在自动更新的覆盖清单中。

真实环境验收应覆盖两端 TCP 53318 放行、主机与副机双向拖拽、桌面/资源管理器落点、悬停提示、传输进度、拖回源屏与 Esc 取消，以及不同 DPI 下的鼠标行为。多机投递需要额外验证副机 A 经主机屏幕拖到副机 B 的完整过程；自动化测试不能替代这些实机检查。

## 发布

开发仓库为 [wtyLaziness/desksend](https://github.com/wtyLaziness/desksend)，下载与更新仓库为 [wtyLaziness/desksend-releases](https://github.com/wtyLaziness/desksend-releases)。

完整便携 ZIP、MSI、对应源码和校验文件同时发布到两个仓库的 Releases，保持附件一致。源码仓库提供直接下载入口，软件内置更新继续查询 desksend-releases。标签应指向该版本的对应源码提交。

通过维护者已登录的 GitHub CLI 创建发布草稿，上传完整包、对应源码和校验文件，核对后公开。标签为 `v<版本>`，完整包必须名为 `DeskSend-<版本>-windows-x64.zip`，与客户端更新解析规则一致。不要把维护者 token 放进应用或仓库。

发布功能变更时同步更新用户指南、随包帮助和两个仓库首页。下载仓库首页正文见 [发布仓库README.md](发布仓库README.md)。更新协议、安装与备份细节见 [发布与更新说明](发布与更新.md)。
