# DeskSend 使用指南

## 准备与安装

两台电脑安装同一版本的 Windows x64 完整便携包。下载入口为 [DeskSend Releases](https://github.com/wtyLaziness/desksend-releases/releases/latest)。

下载 `DeskSend-<版本>-windows-x64.zip`，完整解压到可写目录，运行 `DeskSend.exe`。不要在压缩包预览中直接运行，也不要只复制 EXE。`localsend-cli.exe` 是后台组件，不需要手动打开。

## 主机与副机配置

**主机 Server** 是连接实体键盘、鼠标的电脑：

1. 选择“使用此计算机的键盘和鼠标（将此计算机设为服务器）”。
2. 打开“配置服务器”，添加副机屏幕，将它放在主机左、右、上或下的实际方向。
3. 将副机屏幕名称设置为副机 DeskSend 界面显示的计算机名，保存并启动。

**副机 Client** 使用主机的键盘、鼠标：

1. 选择“使用另一台计算机的鼠标和键盘（将此计算机设为客户端）”。
2. 填入主机的局域网 IPv4 地址并启动。可以在主机界面查看地址，或在主机终端运行 `ipconfig`。不要填写表示副机自身的 `127.0.0.1`。
3. 首次连接如出现证书指纹确认，核对后信任。之后将鼠标移到配置的边缘，检查能否跨屏操作。

主机停止后，副机保持运行会尝试重连。主机重新启动后通常无需重新启动副机。

## 拖动文件与文件夹

在主机桌面或资源管理器中选中一个或多个文件、文件夹，按住左键拖向副机方向的屏幕边缘。鼠标跨到副机后，在目标位置松手，DeskSend 就会开始发送。

发送端和接收端显示传输状态、字节进度以及完成或失败结果。源文件保留在主机。传输期间鼠标可以回到主机继续使用；无需等文件传完再回切。

松手前按 Esc 或拖回主机可取消本次拖拽。关闭主机键鼠连接会影响后续拖拽，请等当前传输完成后再退出或更新。

### 文件落点

| 副机上松手的位置 | 接收行为 |
| --- | --- |
| 桌面 | 放到副机桌面目录 |
| 打开的资源管理器文件夹 | 放到该文件夹 |
| 其他应用窗口 | 放到默认接收目录，并提供文件剪贴板回退，可在支持粘贴文件的位置使用 Ctrl+V |

默认接收目录优先使用副机“下载”目录，系统未提供该路径时回退到桌面。嵌套文件夹保留层级；空文件夹不传输。大量文件受命令行长度限制时，可先压缩成一个文件再传。

## 更新

使用“帮助 → 检查 DeskSend 更新”，然后下载并安装重启。英文界面中可在 Help 菜单找到“检查 DeskSend 更新…”入口。

内置安装更新适用于可写目录中的便携版桌面模式。它会核对更新包和包内文件哈希，备份待覆盖程序文件，保留整个 `settings` 目录。备份位于当前安装目录的 `.desksend-backups` 中。

手动更新时：

1. 退出旧版 DeskSend，等待文件传输结束。
2. 将新的完整包解压到新目录。
3. 把旧目录的整个 `settings` 目录复制到新目录，覆盖新包的默认 `settings`。
4. 运行新目录中的 `DeskSend.exe`。如更换了程序目录，检查防火墙是否允许新路径。

`settings/Deskflow.conf` 保留旧名称是兼容设计，不要自行改名。正常升级不需要重新生成证书或清空配对。

## 常见问题

### 鼠标连接超时

检查主机是否已启动 Server、副机填写的主机地址是否正确，以及两台电脑是否处于可互相访问的局域网。主机需要允许入站 TCP 24800。

可在副机 PowerShell 中检查，先将示例地址替换为实际主机地址：

```powershell
Test-NetConnection 192.168.1.10 -Port 24800
```

若 `TcpTestSucceeded` 为 `False`，优先检查地址、主机监听、防火墙和无线网络的客户端隔离设置。

### 鼠标能跨屏，但文件不传

先确认两端使用完整包，且核心旁边存在 `localsend-cli.exe`。副机的后台接收组件使用入站 TCP 53318，Windows 可能不会为后台进程弹出放行提示。

在主机上将示例地址替换为实际副机地址后检查：

```powershell
Test-NetConnection 192.168.1.11 -Port 53318
```

只在可信局域网中按需要放行主机 TCP 24800 和副机 TCP 53318。可通过 Windows 防火墙设置允许对应程序。更换解压路径后，也要检查新的程序路径。

1.0.0 存在文件跨屏后立即回弹取消的问题，升级至 1.0.1 或更新版本。若仍失败，查看发送端和接收端日志中的 `FileDropBridge`、`failed` 或 `error` 信息。

### 界面显示英文

在 Edit → Settings → Language 中选择“简体中文”。1.0.1 修正了默认语言代码，并兼容 1.0.0 的错误默认配置；完整包中的 `translations` 目录也要保留。

### 更新提示网络错误或 HTTP 403

GitHub 不可达或匿名接口限流时，稍后重试，或从[发布页](https://github.com/wtyLaziness/desksend-releases/releases/latest)手动下载完整包。按上面的手动更新步骤保留 `settings`。

### 收到文件但不在预期位置

先检查副机桌面、目标资源管理器文件夹和“下载”目录。落在其他应用窗口时使用文件剪贴板回退，可尝试在资源管理器中 Ctrl+V。

### 为什么还看到 Deskflow 名称

DeskSend 基于 Deskflow 和 LocalSend。内部的 `deskflow-core.exe`、`Deskflow.conf`、协议标识及许可证中的原作者名称继续保留。日常入口是 `DeskSend.exe`。
