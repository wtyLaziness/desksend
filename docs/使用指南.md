# DeskSend 使用指南

## 准备与安装

两台电脑安装同一版本的 Windows x64 完整便携包。下载入口为 [DeskSend Releases](https://github.com/wtyLaziness/desksend-releases/releases/latest)。

下载 `DeskSend-<版本>-windows-x64.zip`，完整解压到可写目录，运行 `DeskSend.exe`。不要在压缩包预览中直接运行，也不要只复制 EXE。`localsend-cli.exe` 是后台组件，不需要手动打开。

## 主机与副机配置

**主机 Server** 是连接实体键盘、鼠标的电脑：

1. 选择“使用此计算机的键盘和鼠标（将此计算机设为服务器）”。
2. 打开“配置服务器”，添加副机屏幕，将它放在主机左、右、上或下的实际方向。
3. 将副机屏幕名称设置为副机 DeskSend 界面显示的计算机名，保存并启动。

**副机 Client** 使用主机的键盘、鼠标：

1. 选择“使用另一台计算机的鼠标和键盘（将此计算机设为客户端）”。
2. 填入主机的局域网 IPv4 地址并启动。可以在主机界面查看地址，或在主机终端运行 `ipconfig`。不要填写表示副机自身的 `127.0.0.1`。
3. 首次连接如出现证书指纹确认，核对后信任。之后将鼠标移到配置的边缘，检查能否跨屏操作。

主机停止后，副机保持运行会尝试重连。主机重新启动后通常无需重新启动副机。

## 拖动文件与文件夹

使用**主机共享的鼠标**，在源电脑桌面或资源管理器中选中一个或多个文件、文件夹，按住左键拖过屏幕边缘，在接收电脑的目标位置松手。

| 方向 | 操作 |
| --- | --- |
| 主机 → 副机 | 在主机拖起文件，跨入副机后松手 |
| 副机 → 主机 | 先用共享鼠标进入副机，拖起副机文件，再跨回主机松手 |
| 副机 A → 副机 B | 两台副机连接同一主机，按已配置的屏幕路径拖到副机 B，中途保持左键按下 |

副机自己的实体鼠标不能独立触发跨屏切换。多机投递时，文件由源电脑直接发送到最终接收电脑，不会先保存到经过的主机。

拖入接收电脑后，光标旁会显示松手接收提示。松手后，接收端先显示准备接收，再更新传输进度和结果。发送端也会显示传输状态。源文件保留在源电脑，传输期间可把鼠标移回源电脑继续操作。

松手前按 `Esc` 或拖回源电脑可取消本次跨屏拖拽。传输开始后，在发送端或接收端的进度窗点击「取消传输」，即可结束当前这批传输。接收端已收完的文件会保留，未收完的文件会清理。键鼠连接和排队的其他传输可以继续使用。

### 文件落点

| 接收电脑上松手的位置 | 接收行为 |
| --- | --- |
| 桌面 | 放到接收电脑桌面目录 |
| 打开的资源管理器文件夹 | 放到该文件夹 |
| 其他应用窗口 | 放到默认接收目录，并提供文件剪贴板回退，可在支持粘贴文件的位置使用 Ctrl+V |

默认接收目录优先使用接收电脑的“下载”目录，系统未提供该路径时回退到桌面。嵌套文件夹保留层级；空文件夹和空子目录不传输。文件路径通过标准输入交给后台组件，不再将整份路径列表拼到命令行中。

## 更新

使用“帮助 → 检查 DeskSend 更新”，然后下载并安装重启。英文入口为 `Help → Check for DeskSend Updates...`。

内置安装更新适用于可写目录中的便携版桌面模式。它会核对更新包和包内文件哈希，备份待覆盖程序文件，保留整个 `settings` 目录。备份位于当前安装目录的 `.desksend-backups` 中。

手动更新时：

1. 等待文件传输结束，再退出旧版 DeskSend。
2. 将新的完整包解压到新目录。
3. 把旧目录的整个 `settings` 目录复制到新目录，覆盖新包的默认 `settings`。
4. 运行新目录中的 `DeskSend.exe`。如更换了程序目录，检查防火墙是否允许新路径。

`settings/Deskflow.conf` 保留旧名称是兼容设计，不要自行改名。正常升级不需要重新生成证书或清空配对。

## 常见问题

### 关闭窗口后 DeskSend 仍在运行

标题栏的 × 默认把界面收进系统托盘。选择托盘菜单中的“退出”会关闭界面、键鼠核心和 DeskSend 后台服务。使用 MSI 安装版时，下次以管理员身份启动键鼠共享会重新启动后台服务。Windows 重启后，先启动 DeskSend 并连接主机，再使用共享键鼠操作副机的 UAC 弹窗。

### 鼠标连接超时

检查主机是否已启动 Server、副机填写的主机地址是否正确，以及两台电脑是否处于可互相访问的局域网。主机需要允许入站 TCP 24800。

可在副机 PowerShell 中检查，先将示例地址替换为实际主机地址：

```powershell
Test-NetConnection 192.168.1.10 -Port 24800
```

若 `TcpTestSucceeded` 为 `False`，优先检查地址、主机监听、防火墙和无线网络的客户端隔离设置。

### 鼠标能跨屏，但文件不传

先确认两端使用完整包，且核心旁边存在 `localsend-cli.exe`。1.0.6 起支持主机与副机双向拖放传文件，接收方（副机或主机）的后台接收组件均使用入站 TCP 53318，Windows 可能不会为后台进程弹出放行提示。

先确认两端键鼠连接已建立，后台接收组件已启动，再在发送端检查；将示例地址替换为接收电脑的实际地址：

```powershell
Test-NetConnection 192.168.1.11 -Port 53318
```

只在可信局域网中按需要放行主机 TCP 24800 以及参与文件接收的主机/副机 TCP 53318。可通过 Windows 防火墙设置允许对应程序。更换解压路径后，也要检查新的程序路径。

建议两端都升级到最新正式版。若仍失败，查看发送端和接收端日志中的 `FileDropBridge`、`failed` 或 `error` 信息。若日志提示端口占用，先检查是否仍运行另一份 DeskSend 或文件接收组件。

### 副机鼠标间歇跳回主机

先确认两端已升级到 1.0.7 或更新版本。1.0.7 修复了保活定时器丢失导致连接超时、指针被重置到主屏中心的问题。若仍复现，记录两端版本、发生时间和连接日志，区分网络断开与拖拽取消。

### Wi-Fi 传文件时副机鼠标卡顿

1.0.9 在 Windows 上为键鼠连接请求更高的网络优先级，文件传输没有固定速率上限。实际效果取决于网卡和接入点是否采用该优先级。

### 打开管理员程序后无法跨屏

在主机打开 Geek Uninstaller、磁盘管理等以管理员权限运行的程序时，鼠标可能无法从该窗口跨到副机。把焦点切到普通窗口后又能跨屏。Windows 会限制不同权限进程之间的输入操作，普通权限运行的 DeskSend 可能受影响。[Deskflow 上游同类问题](https://github.com/deskflow/deskflow/issues/8611)

等待当前文件传输结束，在出现问题的电脑上通过托盘菜单退出 DeskSend，再右击 `DeskSend.exe`，选择“以管理员身份运行”。恢复连接后，让管理员程序保持在前台，再从原来的屏幕边缘试一次。已在 DeskSend 1.0.9 Windows 安装版主机上验证，管理员启动后可以从 Geek Uninstaller 窗口跨到副机。

如果卡住的是副机弹出的提权确认框，请按下面的步骤启用副机的后台服务。

### 副机的 UAC 弹窗无法点击

便携版在普通桌面上接收共享键鼠。需要操作 UAC 时，从发布页下载 1.0.8 或更新版本的 MSI，只在出现 UAC 的副机上安装。安装版也提供双向拖文件功能。

1. 退出副机的便携版（原便携目录中的 `settings` 可留在原处作备份，**不要**复制到安装版目录，否则会按便携模式运行并隐藏后台服务选项）。运行 MSI，将 DeskSend 安装在默认的 Program Files 目录。
2. 以管理员身份启动已安装的 `DeskSend.exe`。在“编辑 → 首选项 → 高级”勾选“使用后台服务 (守护进程)”和“始终以系统身份运行（支持登录界面和 UAC）”。
3. 使用原来的副机屏幕名和主机地址启动，重新核对并信任主机的证书指纹。出现 UAC 时，用主机鼠标移动并点击提示上的按钮，再检查返回普通桌面后的键鼠和拖放。

### 界面显示英文

在 `Edit → Preferences → General → Language`（中文为“编辑 → 首选项 → 常规 → 语言”）中选择“简体中文”。1.0.1 修正了默认语言代码，并兼容 1.0.0 的错误默认配置；完整包中的 `translations` 目录也要保留。

### 更新提示网络错误或 HTTP 403

更新检查遇到 GitHub API 的 HTTP 403/429 时，会自动尝试通过发布页和校验文件获取更新。若回退也失败或 GitHub 不可达，稍后重试，或从[发布页](https://github.com/wtyLaziness/desksend-releases/releases/latest)手动下载完整包。按上面的手动更新步骤保留 `settings`。

### 收到文件但不在预期位置

先检查接收电脑的桌面、目标资源管理器文件夹和“下载”目录。落在其他应用窗口时使用文件剪贴板回退，可尝试在资源管理器中 Ctrl+V。

### 为什么还看到 Deskflow 名称

DeskSend 基于 Deskflow 和 LocalSend。内部的 `deskflow-core.exe`、`Deskflow.conf`、协议标识及许可证中的原作者名称继续保留。日常入口是 `DeskSend.exe`。
