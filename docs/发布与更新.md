# DeskSend 发布与更新

源码开发仓库为 [wtyLaziness/desksend](https://github.com/wtyLaziness/desksend)，下载与更新仓库为 [wtyLaziness/desksend-releases](https://github.com/wtyLaziness/desksend-releases)。两个仓库的 Releases 同步提供完整程序包、对应构建源码和校验文件。软件内置更新继续查询 desksend-releases。

产品版本在 `deskflow-master/cmake/DeskSendVersion.cmake` 中维护。主界面、托盘、关于窗口与 Windows 程序图标统一使用 DeskSend；底层核心、协议、配置和证书路径保留兼容名称。

## 更新流程

“帮助 → 检查 DeskSend 更新”查询公开仓库的最新正式 Release。已有自动检查偏好保留。客户端固定使用 DeskSend 发布源，不再读取旧配置中的 Deskflow 更新地址。

发布标签为 `v<版本>`，便携版更新附件命名为 `DeskSend-<版本>-windows-x64.zip`，MSI 安装版更新附件命名为 `DeskSend-<版本>-windows-x64.msi`。检查分为两条路径：

- **正常 API 查询**：读取最新正式 Release，按当前运行版本形态（便携版或 MSI 安装版）校验对应附件名称、上传状态、指定仓库下载地址、非零大小及 GitHub 提供的 SHA-256 digest；重复查询支持 ETag 缓存。
- **HTTP 403/429 回退**：从发布页的最新版本重定向解析版本号，读取该版本的 `SHA256SUMS.txt`，并查询对应更新包大小。回退同样要求有效的版本、校验值和非零大小。

下载完成后再次核对大小和 SHA-256；校验失败不会进入安装。英文菜单入口为 `Help → Check for DeskSend Updates...`。

用户点击“安装并重启”后退出键鼠共享与界面：
- **便携版**：内置更新脚本复核压缩包及包内文件清单，等待界面退出，只结束当前安装目录中的核心和传输组件，备份所有待覆盖程序文件后安装，始终保留整个 `settings` 目录。覆盖失败会尝试恢复备份并提示日志路径。备份保留在 `.desksend-backups`，更新日志保留在临时目录 `DeskSend-apply-*` 中。
- **MSI 安装版**：内置更新脚本复核 `.msi` 文件的 SHA-256，等待界面与后台核心退出后调用 `msiexec` 覆盖升级（非管理员运行时会弹出标准 Windows UAC 提权确认），完成后自动重新启动 `DeskSend.exe`。

便携版自动覆盖要求程序所在目录可写；GitHub 不可达时检查或下载会明确报错，不影响当前版本使用。首次发布 1.0.0 是新更新渠道的起点，旧版需要手动换用完整包。

## 构建与打包

1. 更新版本、提交代码，运行 `deskflow-win` 与 `localsend-cli-win`。两份产物必须来自同一个完整提交 SHA。
2. 下载同一提交的基础 ZIP、MSI 和 LocalSend CLI。使用 `scripts/package-release.py --deskflow-zip <ZIP> --deskflow-msi <MSI> --localsend-exe <EXE> --macos-tar <macOS-tar.gz> --linux-tar <Linux-tar.gz> --build-commit <SHA> --out <新目录>` 组装发布附件。脚本拒绝生产源码与构建提交不一致的情况。 macOS/Linux tar.gz 与 Windows ZIP/MSI/CLI 必须来自同一构建提交。保留每个 artifact 目录里的 `BUILD_PROVENANCE.json`，脚本默认要求它与对应文件同目录。
3. 运行单元测试并在真实双机环境下核对跨屏拖拽、取消与更新流程；C++ 构建会运行包含发布元数据解析在内的单元测试。
4. 使用已登录的维护者 `gh release create` 将便携 ZIP、MSI、macOS arm64 tar.gz、Linux x64 tar.gz、源码包及 SHA256SUMS 上传至两个仓库。先创建草稿，核对附件后发布。

`desksend-build.json` 记录版本、构建提交、源码提交及所有可覆盖文件的 SHA-256；默认配置不在覆盖清单中。源码包使用 `git archive`，不包含 `.git`、本机证书、运行配置和日志。

## 文档同步

修改用户可见功能后，同时检查根目录 `README.md`、`docs/使用指南.md`、本页、`deskflow-master/docs/` 中的随包帮助，以及 `scripts/package-release.py` 生成的 `README.txt`。 macOS/Linux tar.gz 与 Windows ZIP/MSI/CLI 必须来自同一构建提交。保留每个 artifact 目录里的 `BUILD_PROVENANCE.json`，脚本默认要求它与对应文件同目录。

公开下载仓库的首页正文在 [发布仓库README.md](发布仓库README.md) 中维护；修改后需同步到 `desksend-releases` 仓库根目录的 `README.md`。两个仓库的简介也应与当前功能一致。文档更新不替换已发布版本的附件；随包帮助与 `README.txt` 在下一次打包时生效。

## 图标与兼容名称

DeskSend 图标结合分段圆环与三条波纹，PNG 和包含 16–256 像素尺寸的 ICO 位于 `deskflow-master/src/apps/res/branding/`。原作者版权和许可文本保留。

`deskflow-core.exe`、`Deskflow.conf` 和底层协议等名称用于配置及运行兼容，不随产品展示名称修改。
